Grounded answers with citations

A staff member who asks about the meal allowance deserves the rule in force today, from a clause they are allowed to read, with its id attached so they can check it. Tidewell Freight, a constructed 1,200-person freight forwarder, wants exactly that from its policy assistant. Part 1 · covers answering only from the retrieved clauses

Answer from retrieved

6 min live

The generation step gets the question and the top-3 clauses, and nothing else is allowed to become a policy answer. Not what the model remembers about per diems in general, not last year's rule, not a sensible guess. If the retrieved clauses do not say it, the assistant does not say it either. That one constraint is what makes a citation possible at all: every sentence has a clause behind it, so every sentence has an id to show.

LiveThe answer contract4 min▶

Write the rule down where the generation step reads it, and make it testable: one id format, one place the id goes, one exact sentence for "not in the clauses". A hosted model API, an on-premises model or a template that fills in pre-written answers all sit behind the same contract, which is why the bench can use pre-written answers and still test the parts that matter.

★ The answer contract (constructed for Tidewell)You answer Tidewell staff questions about HR, IT and finance policy. Use ONLY the clauses below. Each clause starts with its id, like [FIN-EXP-2@v5]. After every sentence that uses a clause, put that clause's id in square brackets. Cite only ids that appear below. Never cite a document, a page or a memory. If the clauses below do not answer the question, reply exactly: "I can't answer that from Tidewell policy, so I've opened a ticket." Clauses: [FIN-EXP-2@v5] Meals when travelling. When travelling on business, meals are covered by a daily allowance of SGD 60 in Singapore and up to SGD 90 abroad ... [FIN-EXP-3@v5] Client entertainment. Client entertainment up to SGD 150 per guest ... Question (asker group: staff): What is the per diem for meals when travelling?

Two details carry weight. The id includes the version, so a citation says which text answered, not only which rule. And the "cannot answer" line is fixed text, so the hand-off in session 6 can detect it without parsing prose.

LiveWhy not let it answer from memory?2 min▶

Because memory has no version and no owner. G41 asks about the "per diem", a word that only appears in Tidewell's superseded expenses clause, FIN-EXP-2 v4, which paid SGD 50 a day. The current clause, v5, says "daily allowance" and SGD 60. A model answering from general knowledge of per diems has no way to know that Tidewell changed the rule on 2026-02-01, and nothing to cite if it guesses right. The retrieved clause knows both.

Grounding and citation formats in depth, faithfulness scoring and long-document grounding belong to the RAG course's grounding and citations session. This page takes the narrow side: one clause id per sentence, and a mechanical check on that id.

Real world

Retrieval reduces the problem; it does not remove it. Singapore's Model AI Governance Framework for Generative AI (IMDA and AI Verify Foundation, 2024) names retrieval-augmented generation among techniques "commonly used to reduce hallucinations and improve accuracy". Reduce, not remove. And the 2020 paper that named the approach, Lewis and colleagues, lists "providing provenance for their decisions" as an open research problem. Provenance is not a side effect of retrieval; you have to build it, and then check it.

Part 2 · covers the citation check: in the retrieved set and current

The citation check

6 min live

Every answered question has one cited clause. The bench runs three tests on that id, in this order: was it in the retrieved set, is it the current version, and may this asker read it. Any failure means the answer must not go out. The counts below are what the bench prints when the filters that should prevent each failure are missing.

LiveThree tests on one id3 min▶
TestReadsBench count when it failsWhat the failure is
RetrievedThe top-3 list for this question0 on every rungAn invented citation: the id was never in front of the answer step
CurrentThe superseded flag on the cited version6 at rung 1, 7 at rung 2, 0 at rung 3A stale citation: an old rule answering as if it were new
ReadableThe clause's access group and the asker's group7 at rung 1, 0 from rung 2A leaked answer: the asker was told what they may not read

The first row is honest about the bench: it always cites its top-ranked clause, so test one cannot fail there. A real generation step writes its own brackets and can cite an id it was never shown, which is why the test exists and why the build-along plants one. The six stale citations at rung 1 are G14, G36, G37, G38, G39 and G41, all questions worded in the old policy's vocabulary. Rung 2 adds G46: once the managers-only improvement plan clause is filtered out, the best remaining match is the superseded password clause.

LiveThe check reads the index, so the index must be true2 min▶

Test two reads the superseded flag where the pipeline can see it: on the indexed clause. Session 8's break button re-imports the expenses policy without that flag. On rung 4 the pipeline then sees 0 stale citations and prints GO, while the version register, kept by the document owner, finds 1: G41 answered with the SGD 50 per diem from v4 instead of the SGD 60 daily allowance in v5. The check did its job on the data it was given. Keeping that data true is session 7's register-versus-index diff.

Self-studyA check is not a filter, and you want both2 min▶

The permission filter (session 5) and the current-version filter (session 7) run before ranking and stop the bad clause from being retrieved at all. The citation check runs after the answer and only counts. At rung 3 both filters are on and the check finds 0 leaks and 0 stale citations, which is the point: it proves the filters held on all 54 questions. Remove a filter in a later refactor and the check is what turns red, before a member of staff quotes the wrong allowance back to finance.

Real world

A citation raises trust, so it has to be right. OWASP's Top 10 for LLM Applications (2025) describes overreliance under LLM09 Misinformation as users who "place excessive trust in LLM-generated content", and lists human oversight for critical information among the preventions. A bracketed clause id is exactly the kind of detail that makes a reader stop checking. In a constructed Tidewell case, a staff member claims SGD 50 a day for meals because the assistant said so and cited FIN-EXP-2; finance rejects the claim against v5, and the assistant's credibility pays for a version flag nobody checked.

Part 3 · covers why a passing citation can still be a wrong answer

A real citation that does not answer

5 min live

G49 is a staff member asking "Can I bring my dog to the office?". Tidewell has no policy on dogs. BM25 still finds something, because "bring" appears in the disciplinary hearing clause, where an employee "may bring a colleague or union representative". The cited clause was retrieved, is current and is readable by staff. Every test passes. The answer is still wrong.

LiveWhat the check can and cannot know3 min▶

All three tests are about the clause: where it came from, which version, who may read it. None is about the relation between the clause and the question, and a mechanical check on an id cannot be. The bench's grade for "correct" asks one more thing that only the golden set knows: is the cited key one of the clauses that answers this question for this asker? For G49 that list is empty, so any answer is confident and wrong.

This is why rung 3 is NO-GO even with 0 leaks, 0 stale citations and 41 of 42 answerable questions right (97.6%). It answers the questions nobody should answer: confident wrong answers on 31.6% of medium-risk and 35.7% of low-risk questions, and right hand-offs on only 8.3% of the 12 questions it should not answer.

LiveWhere G49 actually gets caught2 min▶

Twice, in two different places. Before launch, the golden set grades it wrong, which is what the bench's wrong-by-risk-tier numbers count. In production, where no golden set exists, the abstain rule does the work: G49's top score is 1.70, under Tidewell's 3.0 line, so rung 4 hands it off and opens a ticket. That rule is session 6.

Neither is complete. G54, "When is the annual staff party this year?", scores 3.71 against the annual leave clause and is still answered at rung 4; it is the one confident wrong answer left on the GO rung, at low risk. The citation passes, the threshold passes, and only the golden set knows.

Self-studyCan a second model judge relevance?2 min▶

A common next step is to ask a second model whether the cited clause answers the question. How far that grader can be trusted, and how to calibrate it, is metric design, and it belongs to the AI evals course's LLM-as-judge session. This track takes the cheaper, inspectable side: gold keys on every golden question, written by a person who read the policy, and a threshold you can move and watch. No relevance-judging rate is quoted here, because none was read at source.

Real world

Confidence is where the harm lands. NIST's Generative AI Profile (NIST AI 600-1, 2024) defines confabulation as "the production of confidently stated but erroneous or false content", and places the risk where users believe false content, "often due to the confident nature of the response". It also names Information Integrity among its 12 risks. An internal assistant adds a twist: the wrong answer to G49 is quoted correctly from a real clause, with a real id. Nothing in the reply looks invented, which is what makes it believable.

Build-along

A citation checker in Python

★ 22 min · everyone builds

Plain Python 3, standard library only. Nine clause versions from Tidewell's constructed store, five draft answers, the three tests from Part 2 and a grade against the golden set. Four of the drafts use the exact retrieved lists the bench produces; the third is constructed, a draft that cites a clause it was never shown. Run it from an empty scratch folder.

Write the store slice and who may read each group. Nine clause versions copied from Tidewell's constructed store, keyed by the same KEY@version id the answer contract uses. Only three fields matter to the check: the key, the superseded flag and the access group.

★ check_citations.py · part 1, the store (constructed)store = { "FIN-EXP-2@v5": {"key": "FIN-EXP-2", "superseded": False, "access": "all"}, "FIN-EXP-2@v4": {"key": "FIN-EXP-2", "superseded": True, "access": "all"}, "FIN-EXP-3@v5": {"key": "FIN-EXP-3", "superseded": False, "access": "all"}, "FIN-EXP-1@v5": {"key": "FIN-EXP-1", "superseded": False, "access": "all"}, "HR-WFH-1@v1": {"key": "HR-WFH-1", "superseded": True, "access": "all"}, "HR-WFH-1@v2": {"key": "HR-WFH-1", "superseded": False, "access": "all"}, "HR-PERF-1@v2": {"key": "HR-PERF-1", "superseded": False, "access": "managers"}, "HR-PERF-2@v2": {"key": "HR-PERF-2", "superseded": False, "access": "all"}, "IT-ACC-1@v3": {"key": "IT-ACC-1", "superseded": True, "access": "all"}, } READERS = {"all": {"staff", "manager", "hr", "finance", "it"}, "managers": {"manager", "hr"}, "hr": {"hr"}, "finance": {"finance"}, "it": {"it"}}

Write five draft answers as records. Each has the question id, the asker's group, the id it cites and the list that was retrieved. The first, second, fourth and fifth retrieved lists are what the bench retrieves for G41 at rungs 3 and 1, G46 at rung 1 and G49 at rung 3. The third is constructed: a draft that cites the claims-deadline clause it was never shown.

★ check_citations.py · part 2, five draftsdrafts = [ {"q": "G41", "asker": "staff", "cites": "FIN-EXP-2@v5", "retrieved": ["FIN-EXP-2@v5", "FIN-EXP-3@v5"]}, {"q": "G41", "asker": "staff", "cites": "FIN-EXP-2@v4", "retrieved": ["FIN-EXP-2@v4", "FIN-EXP-2@v5", "HR-WFH-1@v1"]}, {"q": "G41", "asker": "staff", "cites": "FIN-EXP-1@v5", "retrieved": ["FIN-EXP-2@v5", "FIN-EXP-3@v5"]}, {"q": "G46", "asker": "staff", "cites": "HR-PERF-1@v2", "retrieved": ["HR-PERF-1@v2", "IT-ACC-1@v3"]}, {"q": "G49", "asker": "staff", "cites": "HR-PERF-2@v2", "retrieved": ["HR-PERF-2@v2", "HR-WFH-1@v2"]}, ]

Write the check, in the bench's order. Retrieved first, because an id that was never retrieved may not even exist in the store. Then current, then readable. Return on the first failure so each draft gets one reason.

★ check_citations.py · part 3, the checkdef check(d): cid = d["cites"] if cid not in d["retrieved"]: return "FAIL not in the retrieved set" c = store[cid] if c["superseded"]: return "FAIL superseded version" if d["asker"] not in READERS[c["access"]]: return "FAIL asker may not read it" return "pass" passed = [] for d in drafts: result = check(d) print(d["q"], d["cites"].ljust(13), result) if result == "pass": passed.append(d)

Grade the survivors against the golden set. Gold keys come from session 3. An empty set means no Tidewell policy answers the question, so any answer to it is confident and wrong.

★ check_citations.py · part 4, the gradeGOLD = {"G41": {"FIN-EXP-2"}, "G49": set()} # empty set: no policy answers it print("graded against the golden set:") for d in passed: key = store[d["cites"]]["key"] if key in GOLD[d["q"]]: print(" ", d["q"], "right") else: print(" ", d["q"], "confident and wrong")

Run it and read every line. python3 check_citations.py prints exactly this. Three FAIL lines means each test caught its planted case; the last line is the one the check could not catch.

★ OutputG41 FIN-EXP-2@v5 pass G41 FIN-EXP-2@v4 FAIL superseded version G41 FIN-EXP-1@v5 FAIL not in the retrieved set G46 HR-PERF-1@v2 FAIL asker may not read it G49 HR-PERF-2@v2 pass graded against the golden set: G41 right G49 confident and wrong

Wire it where it belongs. In production, a FAIL means the answer is not sent: the assistant uses the fixed "cannot answer" line and opens a ticket, which session 6 builds. The grade never runs in production, because there is no golden set for a new question; it runs on every change before launch, and its wrong-by-risk-tier counts feed the go/no-go in session 8.

Homework

Before session 5

30 min
  1. Write the answer contract for your own assistant: the id format, where the id goes, and the exact "cannot answer" sentence. Show it to one person who will read the answers and ask whether they could check a citation in ten seconds.
  2. Add a fourth test to the checker: every number in the answer must appear in the cited clause's text. Plant a draft that cites FIN-EXP-2@v5 but says SGD 50, and make the test catch it.
  3. Take five questions your helpdesk gets that no policy answers. Run them through any keyword search over your own documents and write down which clause each one would cite. Count how many pass all three tests.
  4. Find one place in your current documentation where a rule changed but the old wording is still what people use. Write the pair as clauses with ids, and decide which one a citation should point at.
Check yourself

Three questions

Clear all three and Builder session 4 gets stamped in your passport.

1 · What does the bench's citation check test on the cited clause of an answered question?

Retrieved, current, readable: three facts about the clause. A is a stricter grounding test the homework adds; D is an LLM-as-judge question that belongs to the AI evals course. C ignores the filters, which is exactly how a superseded clause wins.

2 · At rung 3, G49 ("Can I bring my dog to the office?") cites the disciplinary hearing clause and passes every test. What catches it?

The check is about the clause, not the clause's relation to the question, so no version of it catches G49. A bigger top-k changes nothing about the top clause. The thumbs grade passes rung 3, which the board rejects.

3 · After session 8's break button, the old expenses version is indexed as current and G41 cites FIN-EXP-2 v4. What does the citation check report?

The pipeline sees 0 stale citations and prints GO; the register finds 1, the SGD 50 per diem. A check is only as true as the metadata it reads, which is why session 7 diffs the register against the index. FIN-EXP-2 is readable by all staff, so D is wrong.
